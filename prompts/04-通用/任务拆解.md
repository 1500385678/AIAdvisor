# 任务拆解(把"模糊大目标"压成"可执行步骤链"的元 prompt)

> 场景:用户说"帮我做个 XX"——但"XX"通常是模糊大目标(做一款产品/写一份报告/组织一场活动/排查一个故障),AI 直接硬答会**想到哪说到哪**,输出散乱、缺依赖、没验收。本 prompt 用于**强制 4 级拆解**(目标 → 子目标 → 任务 → 步骤),把"模糊大目标"变成"可勾选的步骤清单",让 LLM 输出的可执行性提升一个档。
> 适用模型:Claude Sonnet/Haiku · GPT-4o/mini · Gemini Pro/Flash · 国产(DeepSeek/通义/Kimi) · 难度:⭐
> 作者/日期:31-智能 cron · 2026-09-08
> 对应模块:AIAdvisor §3 模块 2「提示词库」+ 跟 04-通用/角色设定 配套(角色 + 拆解 = 完整任务流)

## 提示词

```
你是一位顶级的任务拆解专家(曾在 FAANG/麦肯锡/中科院带过 50+ 大型项目),擅长把"模糊大目标"拆成"3 天内可启动、1 周内可验收"的步骤清单。

请按以下 4 级结构拆解用户的【目标】:

## 1. 总目标(SMART 化)
- 把用户原话改写成 1 句 SMART 目标(Specific / Measurable / Achievable / Relevant / Time-bound)
- 明确【不做什么】(out of scope),避免后续 scope creep
- 估算总工时(人·天)和关键里程碑节点

## 2. 子目标(3-7 个 · MECE 原则)
- 按"交付物"切分,每个子目标对应 1 个**可独立验收的产出**(报告/代码/方案/原型)
- 子目标之间**显式标注依赖关系**:`前置`/`并行`/`可选`
- 每个子目标标注【风险】(技术/资源/外部依赖,1-3 句)

## 3. 任务(每个子目标拆 3-8 个 · RACI 简化)
- 每个任务 = 1 个角色 + 1 个动作 + 1 个产出(动词开头,如"调研 X 选型")
- 标注【所需资源】(人/工具/数据/预算)
- 标注【预估工时】(小时/天)和【最晚开始日】(由依赖关系倒推)

## 4. 步骤(每个任务拆 3-10 个 · 操作级)
- 每个步骤 = 1 个**今天可执行的动作**(打开某个文件/查某条 API/写某段代码)
- 步骤粒度:让一个中等水平的执行者**不需要再问问题**就能开干
- 显式标注【阻塞检查点】:哪个步骤会卡住、需要外部输入(数据/审批/资源)
- 显式标注【回滚点】:哪一步走错可以低成本回头

【输出格式】
- 4 级结构(总目标 → 子目标 → 任务 → 步骤),从粗到细
- 每级用 Markdown 标题 + 表格(交付物/依赖/工时/风险/验收)
- 关键路径(Critical Path)用 **粗体** 标注
- 步骤列表超过 10 个时,自动用【编号 1.1.1.1】的多级编号
- 结尾给【风险地图】(1 段话讲清最大的 3 个风险 + 应对预案)
```

## 适用边界

- **适用**:任何"模糊大目标"启动前的**第一次拆解**——"做一款 App / 写一份行业报告 / 组织一次会议 / 排查一个复杂故障 / 设计一个 Agent"
- **适用**:跨团队协作项目,需要把"我的部分"和"别人的部分"切清楚(RACI 简化)
- **适用**:个人 OKR 制定(把 O 拆成 KR,再把 KR 拆成周任务)
- **适用**:Agent 设计——把 Agent 的"输入/工具/记忆/输出/反思"拆成可编码的子模块(对应 AIAdvisor §3 模块 4 Agent 设计画布)
- **不适用**:事实查询(查天气/算账),不需要拆解
- **不适用**:创意发散阶段(还没决定要做什么时,先头脑风暴,确定方向后再拆)
- **不适用**:单步可完成的简单任务(用户问"这段代码为什么报错",直接答,不要让用户填 4 级表)
- **不适用**:子目标 > 7 个的巨型项目(需要先做"项目集"层切分,再对每个子项目用本 prompt)

## 已知坑

1. **拆解过细 = 反而失控**:用户说"做一款产品"被拆成 200 个步骤,执行者看着清单**反而不会动了**;**步骤总数控制在 50 以内**,超过 = 拆解失败,应该先砍 scope 再拆
2. **粒度不均 = 关键路径失真**:有的任务拆到 3 步、有的拆到 10 步,关键路径会被错估;统一标准:**每个任务 3-8 步、每个步骤 30min-4h**,超出范围就是拆错粒度
3. **遗漏隐性依赖**:两个"并行"子目标其实依赖同一份数据/同一个人(资源冲突),模型会**乐观估计并行度**;需要在 prompt 里**显式要求"标注资源/人员冲突"**,否则甘特图是假的
4. **SMART 化走形式**:用户原话"做好用户体验",被改写成"提升用户满意度 20%"——但**基线数据没有**,这是假 SMART;**SMART 化时必须显式标注"基线数据缺失 = 目标不可量化,需先调研"**
5. **步骤层写得太抽象**:"调研竞品"作为步骤 = 失败,执行者不知道**打开哪个网站、查哪些维度、产出什么格式**;**步骤必须包含"具体动作 + 具体对象 + 具体产出"三要素**,否则就是任务名搬家
6. **风险地图写得太晚**:很多 prompt 把"风险"放在最后一句,但**真正的风险应该在子目标层就暴露**(技术不可行/资源不可得/外部依赖未确认);**风险后置 = 风险被埋**
