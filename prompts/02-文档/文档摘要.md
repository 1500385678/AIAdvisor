# 文档摘要(长文压缩 + 关键点抽取 + 改写)

> 场景:对长文档(论文 / 报告 / 长文章 / 技术 RFC)产出多长度摘要 + 关键点 + 改写版本,支持"先看摘要决定是否深读"
> 适用模型:Claude (Sonnet/Haiku)、GPT-4o 均可 · 国内模型(DeepSeek/通义)也可用
> 难度:⭐
> 作者/日期:31-智能 cron · 2026-08-28

## 提示词

```
你是一位资深<领域>领域的内容编辑,擅长把长文档压缩成多长度摘要,同时保留可追溯的关键引用。请基于以下信息,按"分长度摘要 → 关键点 → 改写"三段式输出。

【输入】
- 文档:<标题> + 完整正文(或贴关键章节,标注总字数)
- 阅读目的:<决策参考 / 快速了解 / 写综述 / 找证据>
- 目标读者:<工程师 / 产品经理 / 管理层 / 通用>
- 长度偏好:<极简 100 字 / 标准 500 字 / 详尽 1500 字>

【输出格式】
```
## 1. 极简摘要(≤ 100 字)
<2-3 句话,说明"这是关于什么的、核心结论是什么">

## 2. 标准摘要(≤ 500 字)
- 背景:<为什么做这件事>
- 方法:<怎么做的>
- 关键发现/结论:<3-5 个 bullet,带数据>
- 局限:<1-2 条,作者自承的不足>

## 3. 详尽摘要(≤ 1500 字)
- 章节 1:<标题 + 1 段压缩>
- 章节 2:<标题 + 1 段压缩>
- ...
- 跨章节洞察:<作者反复强调的点 / 隐含假设>

## 4. 关键点清单
| # | 类型 | 内容 | 出处(章节/段落) |
|---|---|---|---|
| 1 | 结论 | <一句话> | §3 第 2 段 |
| 2 | 数据 | <数字+单位> | §4 表格 1 |
| 3 | 方法 | <怎么做的> | §2 |
| ... | ... | ... | ... |

## 5. 改写版本(按读者)
- 工程师视角(关注实现细节):<200 字>
- 管理层视角(关注结论与影响):<150 字>
- 通用视角(关注故事线):<150 字>
```

【约束】
- 所有事实必须能在原文中找到,不得编造
- 数字/专有名词/引用必须保留原样
- 不确定的地方标 "[原文未明示]",不替作者下结论
- 关键点清单的"出处"必须精确到章节,便于回查
```

## 适用边界

- **适用**:论文 / 长报告(> 3000 字) / RFC / 行业研究 / 长文新闻 / 会议纪要
- **适用**:需要快速判断"是否值得深读"的场景
- **不适用**:代码文件(应走 `01-代码/code-review.md`)
- **不适用**:数据图表密集的报告(应配合图表 OCR 单独处理)
- **不适用**:法律/医疗等强合规文档(摘要可能丢失关键免责条款)

## 已知坑

1. **多章节交叉引用容易丢**:长文档常在 A 章提 B 章数据,摘要时容易只引一处;关键点清单要主动"全篇扫一遍数字"再填
2. **图表数据丢失**:文字摘要天然不包含图表;若文档图表密集,需明确"图表请看原文档 §X"
3. **"作者未明示"易被模型脑补**:Claude/GPT 都倾向"替作者说完整",必须用 "原文未明示" 强制标记不确定
4. **多长度版本冗余感**:极简/标准/详尽三档容易"内容重复",要明确要求每档"独立组织",不是"详尽 = 极简 + 展开"
