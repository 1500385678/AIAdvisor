# 模型对比实验设计(同任务多模型量化对比)

> 场景:同一个 AI 任务(摘要/翻译/分类/抽取/代码生成/Agent)在多个候选模型(Claude / GPT / Gemini / 国内模型)上跑出**可量化的对比表**,避免"凭感觉选模型"
> 适用模型:Claude Sonnet/Haiku · GPT-4o/mini · Gemini Pro/Flash · 国产(DeepSeek/通义/Kimi) · 难度:⭐⭐
> 作者/日期:31-智能 cron · 2026-08-29
> 对应模块:AIAdvisor §3 模块 1「模型对比实验室」

## 提示词

```
你是一位严谨的 AI 评测工程师,擅长把"哪个模型更适合这个任务"从主观印象转化为可对比、可复现的量化实验。请基于以下信息,产出一份**模型对比实验设计文档**(Experiment Card)。

【输入】
- 任务名:<如 "中文法律合同摘要 / SQL 生成 / 客服意图分类">
- 任务类型:摘要 / 翻译 / 分类 / 抽取 / 代码生成 / Agent 多步推理 / 其他
- 候选模型:列出 3-6 个,标注 provider 与版本(如 Claude Sonnet 4.5 / GPT-4o / DeepSeek-V3)
- 输入样本:3-10 条典型样本(含难度梯度:简单 / 中等 / 困难)
- 业务约束:成本上限(USD/千次)/ 延迟上限(P95 ms)/ 合规要求(数据出境?)

【输出格式】

## 1. 实验假设
- H1:<"在 X 任务上,模型 A 优于 B 的依据">(<30 字,可证伪)
- H2:<...>
- 0 假设:<"无显著差异"作为对照>

## 2. 评测维度(每维度 1-5 分 + 权重)
| # | 维度 | 权重 | 评分锚点(1=差 5=优) | 评测方法 |
|---|---|---|---|---|
| 1 | 质量 | 0.4 | 1=事实错误多 5=可生产 | LLM-as-judge + 人工抽检 20% |
| 2 | 延迟 | 0.15 | 1=>10s 5=<1s | P50 / P95 实测 |
| 3 | 成本 | 0.15 | 1=>$0.1/千次 5=<$0.001/千次 | 单价 + 平均 token |
| 4 | 失败率 | 0.1 | 1=>10% 5=0% | timeout / 拒答 / 格式错 |
| 5 | 边界 | 0.1 | 1=大量拒答 5=稳定兜底 | 极端样本测试 |
| 6 | 合规 | 0.1 | 1=数据出境 5=本地化 | provider 部署地 |

## 3. 实验矩阵
- 样本数:N 条(简单 X / 中 Y / 难 Z)
- 模型数:M 个
- 总调用:N × M 次(单变量控制:温度=0 / system 提示固定 / 同一 input)
- 跑批工具:claude-code / openai-bench / 自研 / 人工
- 预算上限:$X(单次跑完)

## 4. 输出聚合表(最终对比)
| 模型 | 质量分 | 延迟 P95 | $ / 千次 | 失败率 | 加权总分 | 排名 |
|---|---|---|---|---|---|---|
| A | 4.2 | 1.8s | 0.003 | 1% | 3.95 | 1 |
| B | 4.5 | 3.2s | 0.015 | 0% | 3.88 | 2 |
| ... | ... | ... | ... | ... | ... | ... |

## 5. 决策与边界
- 推荐:<模型 A · 理由 3 条>
- 备选:<模型 B · 切换触发条件>
- 不推荐:<模型 C · 致命缺陷>
- 复跑条件:模型升级 / prompt 调整 / 业务规模变化

【约束】
- 不允许"凭印象打分",每条评分必须对应一个可测指标
- 评测样本必须公开(随报告附),否则结论不可复现
- LLM-as-judge 必须用 2 个不同 provider 互校,单家裁判置信度低
- 至少 1 个"陷阱样本"专门测模型是否被诱导(anti-prompt-injection)
```

## 适用边界

- **适用**:模型选型决策 / prompt 调优前后对比 / 升级前后回归 / 国产 vs 海外模型合规对比
- **适用**:Web App / Agent / 内部工具的"核心调用入口"选型(影响 80% 流量的那一两个任务)
- **不适用**:闲聊 / 探索性 brainstorming / 一次性 PoC(成本不划算)
- **不适用**:模型已经稳定的低频任务(直接用历史经验,无需每次跑实验)
- **不适用**:实时性要求 < 100ms 的场景(评测本身延迟就高,选型后单独压测)

## 已知坑

1. **样本偏差**:评测样本若全来自"你自己写过的成功案例",结果一定偏向你熟悉的模型;必须含 ≥ 20% 反例 / 边界样本
2. **温度=0 不等于稳定**:Claude / GPT 在 temperature=0 下仍有微抖动,关键任务要**跑 3 次取众数**,不要只看单次
3. **LLM-as-judge 偏好同源**:GPT-4 评 GPT-4 普遍偏高,Claude 评 Claude 也偏高;**裁判必须与被评模型不同 provider**
4. **成本口径不一致**:Claude 按"输入+输出"分别计费,GPT 按总 token,国产按字符;对比前必须换算到统一单位(USD/千次完整请求)
5. **延迟含冷启动**:首次调用往往 2-3× 后续调用,对比必须用**稳态 P95**,不要被冷启动拉低评分
6. **样本量 < 30 条统计无意义**:小样本下"质量分 4.2 vs 4.4"可能在误差范围内,要附"置信区间"或"是否显著"
