# 标题生成(多版本 · 多场景 · 多字数约束)

> 场景:把一段正文/摘要/技术博客/产品文档/周报产出"可发布的标题",支持多版本对比(直白/悬念/数字/对仗/疑问),适配不同平台(公众号/掘金/知乎/Notion/飞书/邮件/SEO)
> 适用模型:Claude Sonnet/Haiku · GPT-4o · 国产(DeepSeek-V3/通义千问)表现也稳定
> 难度:⭐
> 作者/日期:31-智能 cron · 2026-09-04
> 对应模块:AIAdvisor §3 模块 2「提示词库」+ 36 咨询 Agent 飞书日报/Inspiration 文件命名场景

## 提示词

```
你是一位资深的中文内容主编(10 年以上,服务过科技/财经/教育垂类),擅长为不同平台/不同受众生成"打开率高、信息无损、风格统一"的标题。请基于以下输入,按"标题族 → 平台适配 → 命名建议 → 自检"四段式输出。

【输入】
- 正文:<标题空白的内容>(可贴全文 / 摘要 / 一段话,标注字数)
- 内容类型:技术博客 / 行业研究 / 产品文档 / 周报日报 / 新闻 / 教程 / 评测 / 案例 / 综述
- 目标平台:微信公众号 / 掘金 / 知乎 / Notion / 飞书消息 / 邮件主题 / SEO 网页 / 多平台同步
- 目标受众:<AI 工程师 / 产品经理 / 决策者 / 通用大众>
- 标题字数:<≤ 15 字 / 15-25 字 / 25-35 字 / 35-50 字>;默认"15-25 字"
- 风格偏好:<直白 / 悬念 / 数字驱动 / 对仗 / 疑问 / 引用 / 混合>;默认"直白 + 数字驱动"
- 关键词(SEO/品牌):<必含的词,如 "RAG" / "Agent" / "Cursor">;可空

【输出格式】

## 1. 标题族(≥ 8 个版本,覆盖 5 种风格)
按"风格 + 字数"维度矩阵产出,每条带"风格标签 + 字数 + 适配平台"。

| # | 标题 | 风格 | 字数 | 适配平台 | 备注 |
|---|---|---|---|---|---|
| 1 | RAG 检索的 5 个常见坑 | 直白+数字 | 11 | 公众号/掘金 | 数字驱动 CTR 稳定 |
| 2 | 为什么你的 RAG 答非所问? | 疑问 | 13 | 知乎/公众号 | 痛点共鸣,适合教育向 |
| 3 | 一年踩坑 RAG,我总结了这 5 点 | 引用+数字 | 16 | 掘金/知乎 | 第一人称+时间锚 |
| 4 | RAG 检索:从能用→好用的 3 步 | 对比+数字 | 15 | 公众号/Notion | 进阶感,适老读者 |
| 5 | 5 个 RAG 坑,90% 团队都踩过 | 数字+夸张 | 16 | 公众号 | CTR 高但易标题党 |
| 6 | 深度 \| RAG 检索的工程化陷阱 | 直白+深度 | 14 | 知乎/36kr 风 | 媒体调性 |
| 7 | RAG 不只是 Embedding:全链路 5 坑 | 对比+限定 | 17 | 掘金 | 反常识,信息密度高 |
| 8 | (兜底) RAG 检索优化实践 | 极简 | 9 | 邮件/飞书/SEO | 万能兜底,严肃场景 |

## 2. 平台适配(选 3-5 个最适配,微调措辞)
针对用户指定的目标平台,挑出最匹配的 3-5 个标题,做"平台定制"调整:
- 微信公众号:标题 ≤ 15 字最佳,数字/悬念优先,避免英文(显示不全)
- 掘金:15-25 字,英文/技术术语保留,符号可用 [ ] / 【】 突出
- 知乎:25-35 字可,疑问/争议性更易获赞,但避免"震惊体"
- 飞书/邮件主题:≤ 20 字,直白优先,别悬念(打开率低)
- SEO 网页:必含"关键词"参数 1-2 次,标题 30-50 字最利收录

## 3. 命名建议(如果是 Inspiration / 文件 / 章节)
如果内容是"可入库的研究/笔记",给 1 条**结构化命名建议**(中文 + 数字前缀,符合 _AILib 约定):
- 格式:`<数字编号>-<主题>-<场景>.md`
- 示例:`05-智能 02-RAG 检索工程化实践.md`
- 不确定时给 2 个备选,让用户选

## 4. 自检清单(8 条,逐条打 ✓/✗)
- [ ] 标题能在 2 秒内说清"读者将获得什么"
- [ ] 关键 SEO 词在标题里出现 ≥ 1 次
- [ ] 没有"震惊/必看/转疯了"等平台限流词
- [ ] 数字/年份/版本号不被"中国化"(2024 改 2024 年是错的)
- [ ] 英文专有名词不强行音译(Agent/RAG/LLM 保留)
- [ ] 字数符合目标平台上限(微信 15 / 掘金 25 / 知乎 35)
- [ ] 没有歧义(读者不会把 RAG 误读为"拽")
- [ ] 标点用全角(,/。/:/?/!)而非半角,符合中文排版

【约束】
- 标题不"标题党":数字/悬念要"信息可验证",不要"5 个坑"实际写 3 个
- 一次只产 1 个最佳标题的 prompt 容易陷入"反复改",改为产 8+ 个让用户挑
- 平台适配必须有针对性,不要"8 个标题通吃所有平台"
- 命名建议符合 _AILib「中文 + 数字前缀」约定(参考现有 01-代码/02-文档 结构)
- 自检清单要可逐条对照,不是"看起来好"就过

## 适用边界

- **适用**:技术博客标题 · 行业研究报告标题 · 产品 PRD 章节标题 · 周报日报标题 · Notion 文档标题 · 飞书消息主题 · 邮件主题
- **适用**:36 咨询 Agent 飞书日报/Inspiration 文件命名(配合 04-通用/角色设定)
- **适用**:SEO 标题优化(网页 title / meta description)
- **适用**:摘要/翻译产出的"再加工"(有了摘要/翻译后,需要标题化)
- **不适用**:文学/诗歌/广告 Slogan 标题(创意性 > 信息性,需独立 prompt)
- **不适用**:已有标题的"优化"(只需小幅调整时,直接 edit,不必调大模型)
- **不适用**:多语言混排标题(中文 + 英文 + 数字,需要单独 prompt 处理混排排版)
- **不适用**:实时热点标题(热点变化快,模型知识滞后,需人工 + 数据驱动)

## 已知坑

1. **"8 个标题全是直白"**:模型默认安全,容易 8 个标题都直白平淡,缺少"悬念/数字/疑问"多样性;必须在 prompt 里强制"覆盖 5 种风格",并给风格示例表
2. **平台特性没适配**:一份 8 个标题贴公众号/掘金/知乎,实际只有 2-3 个真的适配;平台适配段不能省,要**逐平台改字数 + 措辞**
3. **SEO 关键词缺失**:为了"读起来自然"丢掉品牌词,导致搜索不收录;SEO 场景必须**关键词必含**,通过自检清单强制
4. **数字标题党**:为追求 CTR 写"90% 团队都踩过"但实际只写 3 个坑,读者点开失望,二次打开率暴跌;标题数字必须**与正文严格对齐**,自检清单第 1 条强制
5. **英文术语被音译**:把 RAG 译成"瑞格"、Agent 译成"代理",读者一脸懵;强制**专有名词不译**(参考 02-文档/技术翻译.md 同样原则)
6. **命名建议不符合 _AILib 约定**:生成"AI Research Note.md"这种英文命名,破坏了"中文 + 数字前缀"的项目一致性;必须明确**命名格式示例 + 反例**
7. **字数溢出平台**:微信公众号标题 > 15 字会被截断显示"...";自检清单第 6 条要按平台上限逐条核
8. **没给"兜底"标题**:8 个标题全是创意型,正式/严肃场景(邮件/飞书/SEO)无可用;必须**至少 1 个极简直白版**,作为安全网
