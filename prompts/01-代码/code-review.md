# 代码审查

> 场景:对一段代码做"风格 + 逻辑 + 安全 + 性能"四维审查,产出可执行 review 意见
> 适用模型:Claude (Sonnet/Haiku)、GPT-4o 均可
> 难度:⭐⭐
> 作者/日期:31-智能 cron · 2026-08-25

## 提示词

```
你是一位资深<语言>工程师,请对以下代码做四维审查,并按优先级排序输出问题清单。

【审查维度】
1. 正确性:边界条件、异常处理、并发安全、资源泄漏
2. 可读性:命名、结构、注释、复杂度
3. 性能:时间/空间复杂度、可优化点
4. 安全:输入校验、注入风险、敏感信息、权限

【输出格式】
对每个问题按以下结构输出:
- 优先级:P0(必须修)/P1(建议修)/P2(可选)
- 维度:<正确性/可读性/性能/安全>
- 位置:<行号或函数名>
- 问题:<一句话描述>
- 建议:<具体改法,可贴替换代码>

【约束】
- 只输出问题清单,不要重复贴原代码
- 优先级 P0 必须包含具体改法,P1/P2 可只给建议方向
- 整体控制在 200 字以内,问题不超过 5 个

【代码】
<贴代码>
```

## 适用边界

- **适用**:单文件 / 单函数 / ≤ 200 行的代码审查;提交前自检;PR 辅助
- **不适用**:跨文件架构审查;性能 profiling(需 runtime 数据);UI 视觉审查
- **已知坑**:
  - 模型对"业务正确性"判断弱(如订单状态机),需配合人工 review
  - 输出长度限制 200 字,大问题易被截断,需分块喂入
  - 不同模型对"行号"识别精度不同,Claude 最佳,国内模型常需手动指定

## 变体 A · 极简版(只挑 P0)

把输出格式改为:
```
【输出】只列 P0 问题,每项 1 行,格式: 行号-问题-改法
```

适用:CI 集成 / 自动化卡点

## 变体 B · 安全专项版

在审查维度前加:
```
【安全优先】本次仅审查安全维度,其它维度忽略。
额外检查:XSS / SQL 注入 / SSRF / 反序列化 / 硬编码密钥 / 不安全随机数
```

适用:处理用户输入的代码 / 鉴权模块 / 支付链路
